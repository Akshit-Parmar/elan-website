# Recruitment and organiser workflow update

## Where to find OC applications

Before this release: Admin → Organiser inbox, listed as volunteer enquiries.
After uploading this release: Admin → Workspace → OC applications. The Overview also links directly to the application list.

The list recognises existing 2027 committee applications. Review the complete answers, filter by first-choice department or stage, add private notes, record interview arrangements, and move applications through New, Shortlisted, Interview, Selected and Not selected. Review changes have a history and concurrent edits are rejected. Selection does not send an email or grant organiser access. Assign access separately in Committee & access once agreed.

## Included changes

- Dedicated recruitment workspace, with stage counts and a visible Overview shortcut.
- Optional task deadlines at assignment; overdue and upcoming deadlines in organiser task lists. Leaders get department summaries for open work and approvals. Existing role-specific finance, media, design and other tools retained.
- Approval cards show the submitter, time and review round. Both leadership decisions and earlier rounds remain visible. Later/rejected decisions require a note in the panel; later requires revisit planning.
- Crop/framing control for each photo in a bulk upload batch. Existing full-image and single-upload crop tools retained. Drafts, history/restore and gallery reordering retained and verified. Page publication now asks for confirmation after preview.
- Responsive recruitment and organiser controls. Grade/year remains required. Applicant name limit now matches the API's 120-character limit.
- Module dependency check prevents missing JavaScript files in deployment archives.

## Database / deployment

The additive recruitment, deadline, summary and author-label changes have already been applied to the existing elan-v2 Supabase project. Do not run fresh-project.sql on the existing project. The website files have NOT been pushed to GitHub or deployed to Cloudflare by this update. Upload the complete deployment folder using the existing deployment process. Existing content and access assignments remain in place.

The incremental SQL is scripts/recruitment-upgrade.sql, for a project that has all previous upgrades but not this update. It is not a repeatable installer. fresh-project.sql is only for a new, empty database.

## Recovery

Keep the previous ZIP before replacing your GitHub files. If the website needs rollback, restore that release; the additive database fields are compatible with the previous website. Do not reset or restore the whole database to undo a visual deployment. For content, use Edit website → History / restore, preview the recovered draft and publish. Keep a database backup separately from the ZIP; the ZIP does not contain private application records or Supabase Storage uploads.
