# Visual administration update · 2 November 2026

The admin now opens Edit website: a same-origin preview of the real pages, with direct text editing, a photo inspector, desktop/mobile previews, explicit save, discard, original-content restoration and unsaved-change protection. Public visitors cannot see these controls.

Photo overrides are keyed to the page placement. Existing shared asset overrides remain compatible, but new edits do not create shared replacements. Restoring a placement explicitly restores its bundled source, even if an older shared override exists. Guest-directory portraits, guest-profile portraits and gallery images have their own placement keys.

Guests and Gallery have searchable cards and guided add/edit forms. Guest names create their identifiers automatically. Portraits can be added later. The new record defaults to the first edition and draft status; Show on the website publishes it. Public pages and admin previews use the same profile/card builders. New profiles also appear in the people directory. Gallery records retain categories, captions, ordering and photo credits; reserved website replacements never appear as gallery entries.

## Deployment

Upload the package contents to the existing GitHub repository or a preview branch. Cloudflare build: `python3 scripts/build.py`; output: `dist`. Existing Supabase tables, RLS and the admin API are reused. No migration, reset, reseed or backend redeployment is required. The update is not live until the frontend deployment completes.

## Coverage and limits

Visual text editing covers copy across 25 public pages, including navigation, footer text, short labels, form labels and legal policy copy. Guest biographies and gallery captions open their dedicated collection forms. Navigation structure, form behavior, account pages, search metadata and 3D scene geometry remain source-managed. This is a content editor, not a layout builder. Guest directory order follows the order field; established guest profile sections retain their existing page positions and newly added profiles appear before the closing section.

Drafts are available for collection entries. Page edits remain in memory until Save changes publishes them; leaving warns before discarding. Text saves are one batch; image saves are sequential. A failed image save retains the remaining changes for retry. Already-saved changes are not rolled back by a later failure. Uploaded files from failed or abandoned saves may remain unreferenced in storage.

## Layout regression repair

The first visual-editor release inserted ordinary span wrappers around bare text. Existing span-specific CSS then styled the new wrappers as arrow icons, causing the reported homepage overlap. Public HTML now uses invisible comment markers for bare text and retains its exact original element structure. The admin iframe alone creates custom editing handles, avoiding the website's span selectors.

Coverage expanded from selected main-page passages to all supported visible text nodes in headers, footers, navigation, short labels and forms on 25 public pages. Existing content keys are retained through a compatibility map. Guest and gallery records still use the collection forms. Current published wording is unchanged by these annotations.

Verification: all 47 generated pages match the unannotated build byte-for-byte after removing only CMS markers; the original homepage appearance was checked in the browser; the previously broken scroll label and navigation label were selected, and navigation text saved through the isolated fixture. A Python regression test checks exact source preservation and expanded annotation coverage. No live content was changed during these tests.
